## 2. Что уже работает

### Оболочка
* `P3ShellActivity` — единственный LAUNCHER. Ядро (`com.winlator.MainActivity`)
  остаётся доступным из Центра управления как отдельная точка входа.
* Четыре вкладки, «назад» на экранах модулей, восстановление последней вкладки.

### Игры и контейнеры
* Игра и контейнер — разные сущности: много игр на контейнер, у игры свой
  профиль запуска.
* Профиль пишется в секцию `[Extra Data]` ярлыка `.desktop` перед стартом.
  Контейнер не изменяется — две игры в одном контейнере не конфликтуют.
* Ярлык создаётся автоматически, если его нет.

### GPU
* Каталог драйверов из компонентов ядра, установка, активация.
* **Снимок на контейнер**, откат по контейнерам (`rollbackAll`).
* Проверка типа компонента: Turnip → `TURNIP`, Gladio → `ADRENOTOOLS_DRIVER`.

### Engine HUD
* Источник кадров — то же событие `WindowManager.onUpdateWindowContent`,
  что использует штатный счётчик кадров ядра, поэтому числа совпадают.
* FPS, frame time, RAM, CPU, температура и частоты — из `CPUStatus`.
* Оверлей не перехватывает касания: ввод уходит в `TouchpadView`.

### Fail-Safe
* `CrashGuard` — Java-исключения: стектрейс в файл синхронно + счётчик серий.
* `GameLogCapture` — stdout/stderr процесса через `ProcessHelper`
  (подписка заодно отключает перенаправление в `/dev/null`).
* `GameLogCapture.diagnose` — разбор типовых причин: SIGILL (AArch32 на
  Cortex-A720/A520), SIGSEGV (драйвер), SIGBUS, отказ dlopen Vulkan, DLL.
* Три падения за минуту → безопасный режим. В безопасном режиме
  GPU-оверрайды профиля отбрасываются при запуске.
* Экран «Игра закрылась» с причиной и кнопками в GPU Manager / Диагностику.
  Отчёт переживает запрет фонового `startActivity` (Android 10+) через флаг
  в настройках.

### Статистика
* Сессия = жизненный цикл игровой Activity, активное время без свёрнутых
  участков, флаг аварийного завершения.
* В сессии сохраняются условия запуска
  (`драйвер|DXVK|Box64|разрешение|профиль|безопасный режим`) и причина сбоя.
* Экран статистики игры: время, число запусков, аварийные сессии, история.

### Ввод
* 53 раскладки `.icp` в APK, импорт без интернета через штатный
  `InputControlsManager` (id и дедупликация — как у ядра).
* Редактор раскладок — штатный `ControlsEditorActivity` ядра (P3 передаёт
  `profile_id`), свой редактор не дублируется.

## 3. Что осталось

1. **Релизный инструментарий**: подписанный APK, changelog, проверка
   `verify_assets.sh --strict` в CI-шаге сборки.
2. **Проверка на устройстве**: ни одна фаза не собиралась компилятором
   (в песочнице нет JDK/SDK). Первый `assembleDebug` на машине разработчика
   может выявить опечатки, которые статический анализатор не видит.
3. **Переименование пакета** — см. `docs/02_PACKAGE_RENAME.md`.
4. **Достижения**: таблица есть, начисление реализовано частично.

## 4. Как проверять

```bash
python3 scripts/p3_static_check.py     # синтаксис, импорты, R.*, XML, слои
bash scripts/verify_assets.sh --strict  # контрольные суммы вендорных .tzst
```

Статический чекер проверяет в том числе:
* `com.winlator` не зависит от `com.p3win` (зависимость строго односторонняя);
* нет захардкоженных `/data/data/com.winlator` вне `P3Application`;
* каждый `R.*` существует в ресурсах;
* каждый P3-файл с ресурсами импортирует именно `com.winlator.R`.

## 5. Границы, которые нельзя нарушать

| Правило | Причина |
|---|---|
| Весь новый код в `com/p3win/` | обновление ядра не должно требовать ручного merge |
| `com.winlator/**` без изменений | то же |
| Никаких абсолютных путей к data-dir | смена `applicationId` должна оставаться возможной |
| Нет Room и новых Maven-зависимостей | сборка должна работать без сети |
| `applicationId` = `com.winlator` | rootfs, ICD и JNI зашиты на этот путь |
