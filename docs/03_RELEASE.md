# P3WIN — сборка и выпуск

> Короткая версия: `powershell -ExecutionPolicy Bypass -File .\scripts\release.ps1`
> Скрипт сам останавливается, если не пройдены статические проверки, изменено
> ядро или не сходятся контрольные суммы артефактов.

---

## 1. Что нужно на машине

| Компонент | Версия | Зачем |
|---|---|---|
| JDK | 17 | AGP 8.4.2 |
| Android SDK | compileSdk 35, Build-Tools 34+ | сборка и `apksigner` |
| NDK | 24.0.8215888 | 6 нативных модулей ядра |
| CMake | 3.22.1 | то же |
| Python | 3.x + `javalang` | `scripts/p3_static_check.py` |
| Git Bash / WSL | — | `scripts/verify_assets.sh` |

`pip install javalang` — единственная зависимость статического анализатора.
Она нужна **только на машине разработчика**: ни APK, ни сборка от неё не зависят.

## 2. Порядок

```powershell
# 1. окружение (JDK, NDK, CMake, Build-Tools, sdk.dir)
powershell -ExecutionPolicy Bypass -File .\scripts\check_env.ps1

# 2. релиз целиком: проверки -> сборка -> подпись -> SHA-256
powershell -ExecutionPolicy Bypass -File .\scripts\release.ps1
```

Флаг `-SkipBuild` собирает только проверки — удобно перед коммитом.
Флаг `-SkipAssets` пропускает сверку `.tzst` (например, если артефакты ещё
не восстановлены через `bootstrap_assets.sh`).

## 3. Что именно проверяет release.ps1

1. **`java` в PATH** — иначе Gradle упадёт через две минуты в непонятном месте.
2. **`git status` по `app/src/main/java/com/winlator`** — ядро должно быть
   нетронутым. Это архитектурное правило проекта: вся работа идёт в
   `com/p3win`, иначе обновление Winlator превращается в ручной merge.
3. **`p3_static_check.py`** — синтаксис, импорты, существование каждого `R.*`,
   XML, отсутствие захардкоженных путей, односторонность зависимостей.
4. **`verify_assets.sh --strict`** — SHA-256 всех вендорных `.tzst`.
5. **Сборка** `:app:assembleRelease`.
6. **Подпись** через `apksigner`, если заданы переменные окружения.
7. **`dist/P3WIN-<версия>-<вариант>.apk`** + `SHA256SUMS.txt`.

## 4. Подпись

Ключ **не хранится в репозитории.** Переменные окружения:

```powershell
$env:P3_RELEASE_STORE_FILE     = "D:\keys\p3win.jks"
$env:P3_RELEASE_STORE_PASSWORD = "..."
$env:P3_RELEASE_KEY_ALIAS      = "p3win"
$env:P3_RELEASE_KEY_PASSWORD   = "..."
```

Если `P3_RELEASE_STORE_FILE` не задан, release собирается **неподписанным** —
это нормальный режим для локальной проверки, но такой APK нельзя ставить на
устройство как обновление.

Создание ключа (один раз, хранить отдельно от репозитория и с резервной копией):

```powershell
keytool -genkeypair -v -keystore D:\keys\p3win.jks -alias p3win `
    -keyalg RSA -keysize 4096 -validity 10000
```

> Потеря ключа = невозможность обновить приложение у пользователей без
> удаления и повторной установки (данные контейнеров при этом теряются).

## 5. Чек-лист перед публикацией

- [ ] `release.ps1` прошёл целиком без `FAIL`.
- [ ] `versionCode`/`versionName` обновлены в `app/build.gradle`
      (`versionCode` держим **ниже** upstream-овских 33, чтобы P3WIN не
      «обновил» установленный Winlator).
- [ ] APK установлен на **realme P3 5G** и проверено:
  - [ ] первый запуск: установка rootfs, экран «Система готова»;
  - [ ] создание контейнера, запуск контейнера (рабочий стол Wine);
  - [ ] добавление игры, запуск, HUD (FPS/CPU/температура);
  - [ ] GPU Manager: активация драйвера, откат;
  - [ ] импорт раскладки из APK без сети;
  - [ ] намеренное падение игры → экран «Игра закрылась» с причиной;
  - [ ] три падения подряд → безопасный режим включён и виден в Центре.
- [ ] `SHA256SUMS.txt` приложен к релизу.
- [ ] В `docs/01_PHASE_MAP.md` отмечен статус фазы.

## 6. Чего в этом репозитории нет

* **Компиляции в песочнице.** Все фазы разрабатывались без JDK/SDK, проверка —
  `p3_static_check.py` + `javalang`. Первый `assembleDebug` на машине с
  Android Studio может показать опечатки, которых анализатор не видит.
  Это ожидаемо и не означает, что архитектура неверна.
* **CI.** Сборка требует ~141 MB вендорных артефактов и полного NDK, поэтому
  автоматический CI-шаг пока не настроен.
